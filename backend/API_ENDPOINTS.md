# Contrato de endpoints — AquaVitae

Desenhado em 2026-09-17 a partir da leitura integral dos mockups Figma (29 ecrãs + 2 popups) e do
cruzamento com o schema Oracle (`database/ddl/`) e o backend atual. Este documento é a fonte da verdade
para a implementação do backend e do contrato Retrofit no Android — substitui a secção "Endpoints
principais" do `backend/README.md` assim que os itens novos forem implementados.

Legenda: ✅ já existe e cobre a necessidade · 🔧 existe mas precisa de ajuste · 🆕 novo endpoint.

## Decisões tomadas (2026-09-17)

1. **Registo em 2 fases.** `POST /api/auth/register` continua a aceitar só `username/email/password`
   (+ opcionalmente `firstName/lastName`) e devolve logo o token. Os restantes passos do wizard (nome,
   nacionalidade/bio, avatar, bebidas preferidas, castas, acidez, doçura) usam os endpoints autenticados
   de perfil/preferências — os mesmos que servem para editar depois. Permite ao utilizador sair a meio e
   retomar (fica só autenticado, sem perfil completo).
2. **Produtor em destaque é computado**, sem coluna/tabela nova: a API escolhe deterministicamente com
   base na semana do ano (rotação entre produtores ordenados por rating médio das suas bebidas). Sem
   curadoria manual por agora.
3. **`casta` passa a distinguir tinta/branca** via tabela de lookup `casta_tipo` (FK), consistente com o
   padrão do resto do schema (`vinho_corpo`, `vinho_tanino`, `vinho_tipo`, ...) — não uma coluna solta.
4. **Recuperação de password por código** — nova tabela `utilizador_password_reset`, ver secção seguinte.
5. **Regiões dependentes de país** (filtro do catálogo) — sem tabela nova; a API calcula
   `SELECT DISTINCT produtor_regiao WHERE produtor_pais_id = ?` em vez de introduzir um lookup formal
   (`produtor_regiao` continua texto livre no schema).

## Alterações à BD necessárias antes do backend (camada 1)

Ficheiro novo `database/ddl/04_patch_endpoints.sql` (+ atualizar `01_tables.sql` como fonte da verdade
para quem reconstruir a BD do zero, + adicionar ao `run-migrations.ps1`/`.sh`):

```sql
CREATE TABLE casta_tipo (
    casta_tipo_id     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    casta_tipo_value  VARCHAR2(10 CHAR) UNIQUE -- 'Tinta' | 'Branca'
);

ALTER TABLE casta ADD casta_tipo_id NUMBER;
-- + FK casta.casta_tipo_id -> casta_tipo.casta_tipo_id

CREATE TABLE utilizador_password_reset (
    utilizador_password_reset_id   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    utilizador_id                    NUMBER NOT NULL,
    codigo                            VARCHAR2(10 CHAR) NOT NULL,
    expira_em                         TIMESTAMP NOT NULL,
    usado                             NUMBER(1) DEFAULT 0 CHECK (usado IN (0, 1)),
    data_criacao                      TIMESTAMP DEFAULT SYSTIMESTAMP
);
```

Seed: popular `casta_tipo` para as 250 castas existentes a partir das duas listas do Figma (tintas /
brancas) — texto já capturado, falta só o `UPDATE` em massa no seed.

## Imagens (bebidas, produtores, avatares)

`bebida_path_image` e `produtor_path_imagem` existem no schema mas **nunca foram populadas** no seed —
ainda não havia decisão sobre onde as imagens ficam alojadas.

**Decisão:** para o MVP, sem infraestrutura de CDN/bucket, as imagens ficam como recursos estáticos do
próprio backend Spring Boot (`backend/src/main/resources/static/...` — Spring serve automaticamente
qualquer ficheiro aí, sem controller nenhum). O Android resolve a imagem completa como
`API_BASE_URL + path`. Mesmo padrão a seguir depois para fotos de bebidas/produtores, quando existirem.

**Avatares — feito (2026-09-18).** 27 avatares (SVG, desenho de linha, 9 por categoria: Castas/Garrafas/
Copos) entregues pelo utilizador e integrados:
- Ficheiros em `backend/src/main/resources/static/icones/avatares/*.svg`, servidos em
  `GET /icones/avatares/<slug>.svg` (content-type `image/svg+xml`, confirmado a correr).
- `avatar_path_image` no seed/BD guarda o path relativo `icones/avatares/<slug>.svg`.
- `avatar_categoria` tem agora as 3 categorias reais (substituindo o placeholder do esqueleto
  "Animais"/"Geométrico"/"Ilustração").
- Spec de design completa (cores do traço, escalas por contexto, estado selecionado/hover) documentada em
  `backend/src/main/resources/static/icones/avatares/README.md` — consultar ao construir o ecrã de
  escolha de avatar no Android.
- `SecurityConfig` liberta `GET /icones/**` sem auth (recursos estáticos públicos).
